# local-repo-monitor

A light-weight web application which provides a simple interface over your local repositories, it keeps track of their git status, any staged/un-staged changes, branches etc... This tool is intended to be run as a Docker Container that sit's in the background performing periodic health fetches.

This application is mostly generated by Opus 5.6, however, I have reviewed every line of the actual implementation as well as the UI choices .

Feel free to clone this repo and make any changes that can help with your workstation.

## Quick start (Docker)

1. Edit the volume path in `docker-compose.yml` to point at the folder
   containing the repos you want to watch (defaults to `D:/Repos`).
2. Run:

   ```bash
   docker compose up --build
   ```

3. Open [http://localhost:3000](http://localhost:3000).

Scanning only ever runs `git fetch` and `git status` - read-only as far as
your tracked files are concerned. The repo-level **Pull** and **Stash**
buttons (see below) do modify your working tree, but only when you
explicitly click them. `git fetch` needs write access to each repo's `.git`
directory (to update `FETCH_HEAD`, objects, and remote-tracking refs), so
the volume mount can't be read-only.

### Private repos

If a watched repo has a private HTTPS remote, `git fetch` will fail with
`could not read Username` unless the container can authenticate. Repos it
can't fetch still show up with their last-known branch/status and an error
message, so this step is optional.

To enable it:

1. Create a [fine-grained personal access token](https://github.com/settings/personal-access-tokens/new)
   scoped to just the repos you're watching, with **Contents: Read-only**
   permission. No other scopes needed.
2. Copy `secrets/.git-credentials.example` to `secrets/.git-credentials`
   (already gitignored) and fill in your GitHub username and the token:

   ```
   https://<your-github-username>:<your-PAT>@github.com
   ```

3. Restart the container: `docker compose up -d --build`.

The file is mounted read-only — the container can use the credentials but
never modify the file. The PAT never touches the app's own code, UI, or
`data/config.json`; it's consumed directly by git's `credential.helper`.

## Configuration

| Env var                | Default   | Description                                   |
| ----------------------- | --------- | ---------------------------------------------- |
| `ROOT_DIR`              | `/repos`  | Folder to scan (inside the container)          |
| `SCAN_INTERVAL_MINUTES` | `5`       | How often to re-scan and re-fetch              |
| `PORT`                  | `3000`    | Port the dashboard listens on                  |

The folder and interval can also be changed from the dashboard UI itself —
this is saved to `data/config.json` and persists across restarts.

## How it scans

Each immediate subfolder of the root directory that contains a `.git`
directory is treated as a repo. If the root directory itself is a repo and
no sub-repos are found, it's scanned directly.

## Repo actions

Click a repo row to expand it and see its staged, unstaged, and untracked
files individually (not just the total count shown in "Working tree").

Each repo row also has two buttons:

- **Pull** — runs `git pull --ff-only`. Never creates a merge commit or
  rewrites history; if the branch has diverged or you have conflicting
  uncommitted changes, it fails with git's own error instead of guessing.
- **Stash** — runs `git stash push --include-untracked` with a message
  containing the current timestamp (e.g. `local-repo-monitor
  2026-10-09T15:54:18.144Z`), so you can find it later with `git stash
  list` and recover it with `git stash pop` or `git stash apply`. Asks for
  confirmation first since it changes your working tree, even though it's
  recoverable.

Both only ever act on a path the server already discovered by scanning -
never on arbitrary input - and are rejected the same way cross-site
requests to `/api/scan` are (see below).

## Security notes

This dashboard has **no login** - anyone who can reach it can see every
watched repo's branch/status and trigger a rescan, pull, or stash. A few
things mitigate that for the intended "runs on your own machine" use case:

- The published port is bound to `127.0.0.1` only (`docker-compose.yml`),
  so it isn't reachable from other devices on your network.
- The container runs as an unprivileged user, not root.
- The scan root can be changed from the UI, but only to the configured
  `ROOT_DIR` or a subfolder of it - not to an arbitrary container path.
- All git calls use `simple-git`'s array-based API (no shell string
  concatenation), so repo paths/names can't be used for command injection.
- All dynamic values rendered in the UI (branch names, error text, etc.) are
  HTML-escaped before insertion - error text in particular can contain
  verbatim text from a remote git server, so this matters.

It's still a plaintext-on-disk credential and an unauthenticated local
server. Don't expose this port beyond localhost, and don't point it at a
folder you don't want its content enumerated.

## Running without Docker

```bash
npm install
ROOT_DIR=/path/to/your/repos npm start
```

Requires Node.js 18+ and `git` on your PATH.
